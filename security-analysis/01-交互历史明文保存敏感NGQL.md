# 默认交互历史明文保存包含凭据的 nGQL

建议英文标题：**Plaintext persistence of credential-bearing nGQL statements in default interactive history**

## 漏洞概述

Nebula Console 默认交互模式会把每一条已经输入完成的非空内容加入命令历史，没有判断或脱敏其中的密码及其他敏感值。进程正常退出时，完整输入会以明文追加到 `.nebula_history`。

因此，以下管理语句可能在会话结束后长期留下可复用的数据库凭据：

```ngql
CREATE USER example WITH PASSWORD 'secret';
```

输入是在本地命令判断和服务端执行之前加入历史的，因此执行成功、语法错误、语义错误或被服务端拒绝的敏感语句都可能被保留。

历史文件以 `0666` 模式打开或创建，最终权限只由进程 umask 修正，可能形成同组可读或其他用户可读文件。即便最终权限为 `0600`，明文长期保存本身仍会使密码进入备份、快照、终端用户后续进程或同一账户被入侵后的读取范围。

## 根因分析

以下行号基于已验证提交：

- `main.go:453`：`--enable_go_prompt` 默认值为 `false`，默认使用受影响的 `liner` 后端。
- `main.go:546`：未提供 `-e` 和 `-f` 时进入交互模式。
- `main.go:548-555`：选择历史目录；`HOME` 为空时回退到可执行文件目录。
- `main.go:604-606`：拼接 `.nebula_history` 并创建交互 CLI。
- `cli/icli.go:28-33`：以 `0666` 创建或打开历史文件并读取旧历史。
- `cli/icli.go:55-66`：所有完整非空输入未经敏感信息判断就调用 `AppendHistory`。
- `main.go:343-356`：在 `ReadLine` 已记录输入后才判断并执行命令。
- `cli/icli.go:111-118`：正常关闭时以追加模式和 `0666` 再次打开文件并写入历史。
- `cli/terminal.go:58-64`：把完整历史项转交给 `liner` 实现。

核心问题是持久化边界缺少敏感输入策略。文件创建权限会扩大影响，但不是唯一根因。

## 动态验证结果

验证使用一次性 NebulaGraph 测试服务、由上述提交编译的客户端、隔离的临时历史目录以及唯一的测试密码标记。

验证结果：

1. 一条包含虚假密码的有效 `CREATE USER` 成功执行。
2. 创建的测试用户随后立即删除。
3. 另输入一条被服务端拒绝的含密码语句。
4. 使用 `:quit` 正常退出交互模式。
5. 隔离 `.nebula_history` 中逐字出现了成功语句和失败语句的测试密码标记。
6. 在验证进程的 umask 下，历史文件最终权限为 `0664`，与源码中的 `0666` 创建模式相符。

验证完成后已删除测试用户和临时历史。未读取任何既有历史或无关数据库数据。

## 复现步骤

请仅在一次性测试环境中使用虚假凭据，不要使用生产密码。

```bash
TEST_HOME="$(mktemp -d)"
umask 0002

env HOME="$TEST_HOME" ./nebula-console \
  -addr 127.0.0.1 \
  -P 9669 \
  -u test_admin
```

在隐藏密码提示中输入一次性测试管理员密码。进入 nGQL 提示符后执行：

```ngql
CREATE USER hist_probe WITH PASSWORD 'HISTORY_TEST_ONLY_8e19c4';
DROP USER hist_probe;
:quit
```

只检查隔离的测试历史：

```bash
grep -F 'HISTORY_TEST_ONLY_8e19c4' "$TEST_HOME/.nebula_history"
stat -c 'mode=%a' "$TEST_HOME/.nebula_history"
```

还可以输入一条服务端必定拒绝且包含另一唯一测试标记的语句，正常退出后再次检查隔离历史，以确认执行失败不会阻止持久化。

### 实际结果

正常退出后，完整 `CREATE USER` 输入及其中的虚假密码以明文存在于 `.nebula_history`。被服务端拒绝的含密码输入同样会被保留。

### 预期结果

包含身份认证材料的输入不应写入持久化命令历史。如果保留历史功能，应在输入到达历史实现之前可靠地排除或脱敏敏感语句及敏感参数。

## 安全影响

能够读取历史文件的主体可以恢复过去 nGQL 中的密码或其他秘密，包括：

- 由最终文件或目录权限允许访问的其他本地账户
- 共享操作系统组的成员
- 备份和文件系统快照操作人员
- 终端管理、取证或支持包采集系统
- 在相同操作系统账户下运行的恶意程序或后续进程

泄露副本的生命周期可能超过 console 会话，甚至超过数据库账户本身。除非安全清理历史并轮换凭据，否则风险会持续存在。

本报告将其定义为本地或执行后的机密性泄露，不主张它本身构成未认证远程攻击。

## 修复建议

1. 在调用 `AppendHistory` 之前实施敏感输入策略，禁止凭据类输入进入历史后端。
2. 使用能够理解 nGQL 语法的解析器或分词器覆盖大小写、空白、引号、多行语句、密码变更和敏感参数命令；不建议只使用大小写敏感的简单正则表达式。
3. 考虑将持久化历史改为显式启用，或者提供适合管理操作的 `--no-history` 选项。
4. 新历史文件强制使用 `0600`，并安全收紧既有历史文件权限。
5. `HOME` 为空时不要把敏感历史回退到可执行文件目录。
6. 为有效语句、失败语句、多行输入、大小写及空白变体增加自动化测试。
7. 在安全公告中提供历史清理和凭据轮换指导。

只修改文件权限并不能彻底修复，因为可复用密码仍会被明文长期保存。

## 范围说明

- `.nebula_history` 通常位于 `HOME` 下，本报告不主张它总是在当前工作目录；仅在 `HOME` 为空时回退到可执行文件目录。
- `-e` 和 `-f` 使用不同的非交互实现，不通过本报告所述路径写入历史。
- 使用 `--enable_go_prompt=true` 时，当前后端的 `AppendHistory` 和 `WriteHistory` 是空实现，因此不会新增当前会话记录；但程序仍会创建并读取共享历史文件，旧敏感记录仍可能存在。
- 异常终止可能使当前会话尚在内存中的记录没有写盘，但不会清除以前的持久化历史。
- 服务端查询日志、传输安全、终端录屏、Shell 历史和进程参数不在本报告范围内。
